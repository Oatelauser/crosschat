## 2. 问题清单（现象→证据→根因→责任环节→严重性）

### A. 消息通道（责任环节：crosschat 工具 + 使用拓扑）

**P1 worker→codex 方向结构性不可用（S1，本轮最大故障）**
- 现象：到达率 11%；三个纪元三种失败模式（硬丢→饿死→拒收）。
- 证据：时间线总账；发件箱 19 条现场；`src/codex/deliver.ts`（busy 120s 轮询）、`src/outbox.ts`（cap 20）。
- 根因：接收方是**常驻 vscode TUI 的活线程**——审查 turn 一跑 20–40 分钟，期间 resume 必 busy/写者被占；投递只能在 turn 间隙挤进去。协议对该拓扑没有豁口（写者锁记忆条 [[codex-writer-lock]]），而当天恰好把决策者放在了最不适合接收的位置。

**P2 排涝饿死 + 队头阻塞 + 新消息插队（S1）**
- 现象：19 条中 #4–#18 的 attempts=0——12+ 小时连一次尝试都没轮到；22:04/22:08 两条新发送却直接送达，越过 3 条更早的滞留。
- 证据：发件箱 attempts 分布（70/44/5/1/0×15）；XCHAT_IN 22:04:19/22:08:11。
- 根因（代码级）：`drain()` 每轮 15s 预算、每条失败烧 5s，队头反复失败吃光预算，队尾永远排不到；新 send 自带 120s busy 轮询而排涝只有 5s——**同一空闲窗口，新消息挤得进去，旧积压挤不进**。

**P3 「空闲后自动补投」承诺虚假 + 无回执 + 发送方盲视（S2）**
- 现象：parked 文案承诺自动补投，实际只在「任何人调 CLI 且恰逢空闲」才发生；delivered 只代表 app-server 接受 turn，不代表对端模型读过；8 次 send 因 Bash 工具层超时转后台，worker 再也看不到最终结果（其中若干实际已 parked）。
- 证据：`send.ts:186` 文案；`outbox.ts` 注释「next CLI call drains」；worker 提取「转后台 8」。
- 根因：无守护/定时器的机会式设计 + 协议无应用层 ack + CLI 生命周期超出调用方工具超时后结果无处落盘。

**P4 OUTBOX_FULL 语义误导（S3）**
- 现象：22:40 起八连拒；报错文案「线程疑似已死：改投其它线程或人工清理」——实际线程活着且在正常收发另一方向。

## 4. 最小整改方案（机制级，均附验收方法/失败判据）

### F1 排涝公平化 + 活性看门狗（修 P2，P0，本仓库）
1. `drain()` 改为**持久化游标轮转**：每线程记录 next-attempt 游标，轮内从游标起试 N 条（失败不占预算、仅成功消耗），队尾必然获得尝试机会。
2. park 后派生一个自续期的短命排涝子进程（`crosschat __drain --delay 30s`，箱空即退；非守护进程，符合无 daemon 约束），打破「双方互等无人调 CLI」死局。
3. 任何命令退出时若箱非空，stderr 必打：`⚠ outbox: 线程X 滞留N条(最旧Y分钟/已试Z次)`。
- 验收：单测（扩展 `test/outbox.test.ts`）：10 条寄存+恒忙线程，跑 3 轮后断言 #4–#9 attempts>0（现状为 0）｜集成：寄存后不再调任何命令，断言 30s+delay 内送达｜失败判据：任何尾项在头项失败 N 轮后仍 attempts=0。
### F2 诚实的 parked/OUTBOX_FULL 语义（修 P3/P4，P0，纯文案+状态输出）
parked 文案改为「已暂存(对方忙)。仅在任意 crosschat 命令运行且对方空闲时补投；长期未回应请 `crosschat doctor`」+ 队列深度；OUTBOX_FULL 区分忙/死并附最旧条目年龄与 attempts，满箱时**溢出转存 mailbox 文件而非拒绝**（见 F6）。
- 验收：快照测试断言新文案含深度/年龄；构造满箱发送断言不再抛错且 mailbox 文件增长。
### F3 接收拓扑指引（修 P1 的使用面，P1，文档+错误文案）
连续两次 parked 的线程，错误输出直接建议：「该线程为 TUI 常驻会话，接收能力受限；改投 headless 信箱会话，或 `codex app-server daemon start` 后重开窗口启用开窗投递」。README 协作拓扑节明确：**决策者若需接收，勿用独占写者的 TUI 线程**。
- 验收：伪造 locked 两次的场景断言提示出现；文档 review。
### F4 发送方异步结果落盘（修 P3 盲视，P1）
send 结果统一追加到 `%LOCALAPPDATA%\crosschat\send-log/<thread>.jsonl`（时间、状态、reply-ref）；`crosschat doctor` 汇总最近结果。「工具层超时转后台」后 agent 可回查。
- 验收：超时转后台场景后读 send-log 断言终态在案；失败判据：任何 send 终态在两个可观测位置都找不到。
### F5 写入边界机制化（修 P12/P16，P0，落 ai-front-spec / 任意协作仓）
1. cc-worker 启动参数 deny `Edit`/`Write`/`NotebookEdit`（Claude Code 权限系统强制，宿主工具通道 100% 堵死）。
2. PreToolUse(Bash) hook：命令匹配 `writeFileSync|Set-Content|Out-File|>\s*\S+\.(md|ts|json|yml)` 且目标在仓库内 → 拒绝并提示 apply_patch（%TEMP% 白名单放行证据文件）。
3. **修掉诱因**：apply_patch 改补丁文件传输（`--codex-run-as-apply-patch-file <path>`），绕开 cmd 8191 截断与多字节参数失配；先做传输模式改造，违规冲动自然消失。
- 验收：①worker 会话内试 Write 被权限系统拒绝（截图/日志）②hook 单测：模拟 I 批/L 批命令样例断言拦截、%TEMP% 样例放行③300 行中文补丁经文件模式原子应用（旧模式在同数据上失败作对照）。
### F6 文件信箱转正（修 P1/P5 借鉴项，P1，协议级）
把当天事实主干道收编进协议：每个 codex 线程配 `%LOCALAPPDATA%\crosschat\mailbox/<thread>.md`，parked/溢出/超 16KiB 的消息同时落信箱；信封教学加一行「对端长期未回应时可只读信箱」。审查者只读信箱 = 当天「落盘+只读」的正式化，不再依赖 agent 自发约定。

### F7 批次状态文件 + 验收清单冻结 + 暂停门（修 P8/P10/P11，P1，落协作仓）
