## Question

跨机 tcp 聊天常需多次进行（一次聊不完是常态），但星成员=启动器一次性声明：会话退出即除名（包装器 detach 主退、聚合器扫描兜底），裸 /resume 恢复上下文不恢复声明——回访必撞 SESSION_NOT_MEMBER。经用户三轮 grilling 定案双模式制，含一次破坏式命令语义变更（用户明示"没人用"窗口期内免费）。

## 模型（定稿）

- **永久册（默认）**：`crosschat claude/codex -n X --connect <星>`——语义从临时挂星**升级为注册入册**（破坏式）。退出=**下线**（册位保留），同 id resume/重启=**自动复活上线**，无需声明（claude 保号四次实证、codex client.ts:136 协议断言）
- **临时（opt-in）**：`--connect <星> --rm`——docker --rm 语义，退出即离册（即今日行为）；一次性 worker 用它（教学写明）
- **extends = 唯一名字转移口**：名字被接任后原会话同 id 回归不夺回（接任者优先）
- **下线投递 = 报错等上线**，绝不静默改投；逃生口 = id8 点对点
- **幂等**：重复注册/删除均无操作成功，永不出现重复条目
- **多星**：各星独立册、独立上下线；复活恢复其所有在线星；`--rm` 作用于同命令全部 `--connect`
- **`--rm` 不触碰机器守护**：聚合器生命周期独立（永久成员的复活检测依赖它活着）；退机器走显式 `serve --stop`。`serve --connect --rm` 组合拒绝

## 命令面

- `--connect` = 永久注册（语义变更）；`--rm` = 临时修饰；`--rm × --extend-session` 互斥报错
- 退出/删除：单一子命令双角色（自退/管理删），按 `名|id8`，幂等（命名实施定稿：--member-remove 或 crosschat member 族）
- adopt = 永久注册（收编活会话，无临时场景）
- **remove 与 adopt 执行边界**：remove 是纯册状态操作（星内任何机器可执——同星共钥=互信域）；adopt 需本地验活（仅会话所在机）——钉死此边界防误开远程状态操作
- `serve --connect` 保留为机器级接入基座（launcher 自动拉起的目标；adopt/member-remove 之家）；文档三动词分层：serve=机器接入、launcher --connect=会话注册、--rm=临时

## 实现基石与存储

- **恢复链常态化**：018 的"broker 告知名单→聚合器本地验活→活的重入册"对账链从重启后一次性扩为**常驻循环**（broker 推 roster→聚合器扫描比对→上报 online/offline 翻转）——复活检测、死亡下线、broker 重启恢复同由一机制承担
- broker 每星一份 roster 落盘（tmp+rename；broker 单写者；无分布式扩展障碍——022 多星=多份独立册）
- 聚合器扫描：死→上报下线（不再除名）；018 测试族 6-8 用例语义改写 + 双模式/复活/幂等/互斥新用例

## 五条边界规则

1. 跨机 resume（册在 M1、id 活在 M2）：拒绝复活+教学"册位绑 M1，迁移走显式操作"
2. `--rm`×`--extend-session` 互斥
3. adopt=永久注册
4. remove 星级可执/adopt 本机限定（见上）
5. `serve --connect --rm` 拒绝

## 有意推翻的 018 设计点（票面明记）

## 明确不做

- TTL/墓碑过期（册是花名册状态不是垃圾）；清理命令（clean 扩展挂账）
- 聚合器引用计数随 --rm 退场（独立生命周期，见模型节）
- 跨机 resume 静默改绑；远程验活类操作
- 单跳 SUPERSEDED、自动改投（沿用 027 不做清单）
