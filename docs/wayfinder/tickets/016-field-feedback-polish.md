## Question

2026-10-13 云端联调现场暴露三点（归档 `../drill-reports/field-feedback-20261013.md`）：

1. **回执机器名显示不一致**：同一对端有时显示友好名（`@yang`）有时显示裸指纹（`@ec542c2c…`）。加重情节：win/WSL **双机同名 yang**，友好名本身有歧义——先查清两种显示各自出现在哪条路径（send 回执 vs 信封回执），再定统一口径（名字带歧义时优先 mid8？）。显示层，不动路由。
2. **回复场景的管道教学缺口**：skill 已有"正文含敏感字符省略 --body 改 stdin 管道"，但写在"主动发起新消息"段，回复场景（hint 给死 `--body`）没说也能换管道形式。修 skill 文案：明确"管道形式适用于一切 send（含回复照抄的命令），把 `--body "<你的回复>"` 换成 `< 文件 |` 或 heredoc 均可"。功能已支持，纯教学。
3. **告别收线约定**：纯告别/收尾消息带 reply-hint，字面照抄会客气乒乓。skill 补一行明文："纯告别或收尾语无需回执，读毕收线即协议完成"。
4. **发送成功后零总结**（用户 2026-10-13 第三次提出，云端联调 Q1 已归档）：各端 agent 普遍把"发送成功即完成本轮"泛化成"每轮写发送小结"。skill 纪律条已改为明文禁令——"直接结束回合：不写发送小结、不复述发送结果、不预告下一步；回执行就是给操作者的全部信息；仅发送失败才说明；收尾总结只在轮次接近预算时做"（**文案已随 2026-10-13 提交落地 skills/crosschat/SKILL.md**，本机已装副本已同步；其余机器待下版 install-skills）。若后续 drill 仍复发，升级方案 = send 成功回执行追加短提示贴脸教学（用户反对新增噪音，暂不做）。
