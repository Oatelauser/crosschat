## Question

一台机器同时只能属于一个星（单文件 node.json）。两个真实场景推动多星：

- **场景 A（用户 2026-10-11 需求 ①b）**：一台机既当自己小星的 broker、又当别家大星的 node——单文件 node.json 一女侍二夫（broker 要存 127.0.0.1 自用凭证，--connect 要存上游地址），现靠"不覆盖+警告"勉强活着
- **场景 B（需求 ②）**：机器要同时入公司星 + 家里星

（需求 ①a——broker 机 colocated 自用——已由 B2.1 自登记解决，无欠账。）

### 方案（2026-10-11 已核路线：wire 不变、加法升级、旧语法永续）

```
~/.crosschat/tcp/node.json            ← 默认档案（今天的一切，永不失效）
~/.crosschat/tcp/nodes/work.json      ← 命名档案
```

- `--connect work` 用 work 档案上线（现有别名参数位扩展；一档案一后台进程）；场景 A 中 broker 自用 127.0.0.1 份即默认档案，外连进命名档案，冲突消失
- 寻址两级：档案数=1 时 `--via tcp:<mid8>` 语义不变；多档案时 `--via tcp:<档案>:<mid8>`，裸写报错教学
- 信封回程路条自动带档案限定词，照抄纪律不变
- 注意点：同一 mid 在两星注册时 mid8 跨星歧义——两级寻址天然消解；roster/status/doctor 多档案分组展示
- broker 全程无感知，proto 号不动
