## 决策（用户 2026-10-20 拍板）

1. **通篇按多星常态写，不区分单星/多星**——032 单形状哲学的自然延伸（册只有 stars[] 一种形状，文档不再教单星心智）。
2. 新叙事骨架：serve=起端口与服务（**永不造星**、零星合法）→ `--add-star`=造每一颗星（首星同，显式命名）→ 管理权限模型（管理员钥匙/本机插座 vs node 拿钥入星自退）→ 热生效语义（加删改星免重启）→ 远程管理 → 会话入星/日常使用（现 §二 主体保留重构）。
3. 写作规矩照旧（doc-style）：文字先行（先人话再命令）、命令→期望输出成对、四股结构、三四章折叠、排障永不折叠。
4. 排障表增：星已删除直报 / 管理员钥匙失效 / 零星态指路。
