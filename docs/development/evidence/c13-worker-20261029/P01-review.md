## Standards 独立审查

由独立 agent 对规范与资源合同审查，两个 P2：

1. 脚本缺少采证有效性总门禁：子进程非零/超时/缺少或损坏 RESULT 不影响退出0；没有 URL 的未探测状态也可被计入“已确认回收”。正常样本可信，但脚本失败路径不能如此宣称验证成功。
2. 超时只调用 kill，没有退出收束截止；error 事件早于 close 即结算，可能在子进程状态未确定时删除根。输出使用字符长度、整块追加，也没有实现声明的严格字节上限。应仅管本次直接启动的子进程，不引入 W05 后代树框架；未确认退出时保留根、明确失败。

## Spec 独立审查

正常对照、两条指定异常路径与白名单范围均满足，额外 mount 错误覆盖观察有用，未测 tmp 双失败边界有声明。以下草案事实与建议需要纠正：

- crosschat 升级不一定改变安装绝对路径，已有指南仅说“改变安装路径时”。
- 同一 Host 内禁用插件正常应触发 disposer，释放自身登记，不能写成必然 dead PID；shellEnv 子 scope 消失只撤身份贡献，HTTP 保留；Host 崩溃才可能留下死 PID 登记。不得合并这三种生命周期。
- 手工 Harness skill 复制不是现有仅两侧 `cpSync` 的执行路径；不得用不适用的实现作为该流程证据。
- 原生 CLI remove 的准确语法及“先 remove 再 add”没有固定依据时，不作为已核实指南；不能把退出 Host 后的 CLI 配置操作直接写成运行中必触发 close。
- “失败后允许重试”不是本单要求，会增加逐资源状态及不明确的第三方 disposer 重试语义。建议下一单仍复用同一 closing Promise：第一次就逐项尝试独立清理，最后保留错误；并发/重复 close 不重复释放。不在本次规划重试状态机。
