## 用户已确认

- 本次启动的 `--rm` 不能默默把已有永久成员改成临时成员。
- 入星对象应跟随用户恢复或选择的原生会话，不固定在启动时首次发现的会话 ID。

- A 切换到 B 时，本窗口释放 A、让 B 入星。A 永久则保留册位，A 临时则清除册位；其他窗口独立工作。
- 规则要统一覆盖 Claude、Codex、OpenCode、DeepSeek Harness 和以后加入的工具，不能只修 Claude。

- TUI 登记的是选定的会话 ID，不绑定原生 GUI 标签页。GUI 切到未登记的 B，不自动给 B 入星；可在 TUI 再选 B。早期“已有永久成员的自动恢复保持”由上文最终统一规则取代。
- TUI 要支持成员增删改查，操作实时生效。手动入星沿用永久成员规则，由 TUI 明确删除退星；不新增永久/临时切换表单，临时成员仍通过 `--rm` 启动管理。
- 不引入星内会话别名。名称以原生会话名为准；可以增加通过原生公开接口进行的非侵入式改名。不能修改原生应用包、直接改历史/数据库或把发出改名文本当成原生命令执行。
- 共享层必须抽象可扩展的工具操作接口。根据稳定工具标识选择适配器，再根据实际能力决定操作是否可用；未来不支持的工具不得在 TUI 执行其不支持的修改。支持能力、运行状态和恢复必须统一处理，不能把判断散落在界面里。
- 能力必须能自动重新核验与恢复：暂时不可用不能永久封禁，工具/连接/版本变化不能继续使用旧能力结论；结果不明的写操作不得当成探测自动重发。
- 安全规则、skill 安全改动和工作目录权限仍排除在当前范围之外。

## 必须区分的身份与状态

原生会话是工具自身的完整会话 ID；星册位是特定星、机器与工具下该会话的成员资格；原生窗口/前端是当前选择会话的所有者。同一个服务进程可以承载多个前端与多个会话，PID 或目录不等于窗口身份。

永久与临时描述的是星内成员资格，不是原生聊天历史的保存方式。一个 A 在 X 星已有永久册位，在 Y 星可能尚未登记；属性必须逐星判断。已有永久成员不能被 `--rm` 重声明、退出清理或死亡清理降级/删除。

| 事件 | 统一目标行为 |
|---|---|
| 启动空白窗口 | 等待选择，不自动认领最新登记 |
| 用户确认恢复 A | 将 A 作为本窗口当前会话，申请指定星的成员资格 |
| 用户开始新对话 | 首条对话输入后，以已确认的原生 ID 入星 |
| A 切换 B | 释放 A 的本窗口声明；永久留册、临时按有效所有权清理；再为 B 建立声明 |
| 窗口退出 | 按当前实际属性释放成员；不连带其他窗口 |
| 普通断网/信号暂不可读 | 保留待核实状态，不把无法核实冒充退出或改挂其他会话 |
| TUI 选定 node 会话入星 | 固定当前星与完整 node/工具/会话 ID；在该 node 重新核验后永久入册 |
| TUI 删除成员 | 立即取消该星的成员资格及按该成员的路由；保留原生会话与其他星 |
| TUI 修改会话名称 | 通过已验证的原生改名能力改真实名称，并核实星内名称/寻址同步；不创建另一套别名 |
| TUI 查看成员 | 显示永久/临时、星籍与原生状态的区别，自动刷新反映其他操作端的变化 |

选择菜单取消、压缩上下文等事件不能误当成选择了新会话。不全局清空 node 成员，不收编无关窗口；原生发现不恢复下线声明，裸 resume 恢复设想已由最终统一入口批准取代。

## 实施前的缺口（历史调查）

- `src/commands/session-star.ts` 的 `run()` 只探测一次 ID，之后监督循环、重连及 `stop()` 都绑定该 ID。PID 精确匹配解决并发归属，不解决同一个窗口中会话切换。
- Claude 有所属子进程 PID；Codex/OpenCode 仍按新增 ID 差分。三者均没有持续的当前窗口选择输入。
- `src/serve/node.ts` 的 attach 直接覆盖本地成员属性；`src/serve/broker.ts` 同样按声明重建册位的 `temporary`。生命周期清理当前复用无条件 `member-remove`，所以仅在一层忽略临时标志不能保护永久成员。
- 当前发现、原生验活、显式 adopt/remove 接口没有窗口生命周期订阅。不能把副作用混入只读发现，也不能用 busy/idle、active、更新时间或 root 列表充当窗口选择。
- DeepSeek Harness 现有入口是 Host bundle，不存在 `crosschat dsh` 启动包装器；不应为追求形式统一而假定已有该命令。
- 本机 `:sessions` 的 `a` 已可收编本机会话；TCP 成员/会话页也有“新增成员”，但 `src/application/tcp/management.ts` 的 `adopt-session` 固定使用 `localCandidates()`，不绑定当前选中的远端 node 会话。这是后端能力缺口，不能只补按钮。
- TCP 已可按完整 node ID 发现未入星会话，也已有远端精确删册；没有对应的远端入星操作通道。旧“收编仅本机”的长期规格需要按本次批准范围更新。
- 当前只有 TCP 节点页持续刷新；成员/会话页主要在自己的动作后刷新。实时管理还需要为这两类列表增加有界自动更新。

## 建议结构

每个工具的适配层提供属于明确窗口/前端的生命周期信号：等待选择、选择成功（完整原生 ID）、新对话首次输入、窗口确实退出、当前无法核实。信号带所属实例和顺序；不需要把提示词或历史正文交给成员监督层。

统一应用层只处理这些信号与本次入星意图，维护可取消的当前会话代次。A→B 后旧的 attach、重连、释放回调不能重新挂回 A 或清掉 B。未来 Provider 接入的是此契约，不要求在共享核心不断添加工具分支。

broker 权威确认逐星的实际永久/临时属性，node 与启动器据此执行清理。清理由“带 `--rm` 就删除”改为核验实际临时资格及声明所有权；显式管理删册仍按现有授权规则处理。窗口释放的是自己的声明，不是该服务下所有同 ID 的使用者。普通重连/重播保留已生效属性，不能把已有永久成员改为临时；本轮不新增 TUI 属性切换功能。

缺少可靠选择信号的适配层必须明确说明能力缺口，不能回退到全局最新会话。已有显式选定完整会话再 adopt 的入口可保留，但不能把它宣称为已支持自动跟随。

## TUI 操作与实时生效

入口为 `TCP → 星 → 节点 → 该节点可发现会话`。在选定行执行“入星”，不再从另一台机器的本地候选列表挑选。星成员视图提供查阅、删除以及在工具支持时的改名；本机与远端入口共用完整身份核验与结果展示。

新增成员请求固定当前连接、星、完整机器 ID、Provider 与原生会话 ID。broker 只路由到该星的指定在线 node，由目标 node 调用自身原生适配层重新核实，不允许发起端用旧列表数据直接构造册位。只操作当前星，沿用现有身份及鉴权，不把只读发现请求改成写请求。

入星成功需要目标 node 执行回执与权威星册确认。删除使用现有精确目标/版本核验，并让在线路由与持久册位一致。改名在原生接口成功后重新读取名称，再核对 node 声明及星内可寻址名称；只改持久标题却无法确认活会话同步时，不能报告完整实时成功。

“实时”分为实际效果与显示更新：本人确认成功后立即生效并重读；其他 TUI 的成员/会话页在活动列表内以有界刷新同步显示。沿用现有 watch 接缝，每2秒刷新；输入、详情、确认等弹层挂起刷新，返回后保持完整目标并重核。不能仅靠刷新界面冒充操作已生效。

操作前目标改变、node 离线、来源无法核实则不发送。操作发出后丢回执、取消或断线显示“待核实”，不自动重发，不伪称已撤回或成功。已有永久成员重复入星保持幂等；已有临时成员不通过普通重复声明隐式转换属性。

## 统一操作接口与能力自动恢复（必须）

### 接口与扩展位置

复用现有 `SessionMembershipService.check/apply` 和 TUI 的 `actionAvailability/checkAction` 接缝，将成员操作与原生改名的复杂判断收进共享应用模块。只读会话发现仍保持只读，不把探测、订阅或写操作偷偷放进 discovery。

共享调用方只需取得完整目标的操作描述，并提交明确操作；其外部契约可归纳为 `describe(target)` 与 `apply(request)` 两类入口。描述返回每项操作的实际能力和状态；提交时再次核验目标、能力和当前条件。最终 TypeScript 命名及与既有接口合并方式由实现决定，不新增未接线的空接口充当完成。

Provider 以稳定 `providerId` 注册适配器，不以可修改的会话名、显示名称或目录选实现。CLI、Desktop、Web 的实际端点、owner 和版本由适配器进一步区分；不能因为都叫 Codex 就复用一个未经核实的修改入口。未来新增工具注册对应适配器即可，通用 TUI 不新增 `if (toolName === ...)` 分支。

每项操作单独报告能力。不能改名不等于不能查看或删除星籍；入星需要原生会话资格核验，删册取决于星内完整成员身份，改名必须具有已验证的原生写接口。未知工具、未注册适配器、缺少能力字段或未核实能力时，相关修改默认不可用，不能默认支持。

### 统一状态与执行契约

| 状态 | TUI 与执行端行为 |
|---|---|
| 可执行 | 当前目标与该操作能力已核实，允许进入确认；提交仍重新核验 |
| 不支持 | 原生工具/该端点不提供所需能力；禁用对应操作并显示原因和原生操作指引 |
| 暂不可用 | 服务断开、繁忙或暂时读取失败；禁用对应修改，保留成员与输入，等待有界重新核验 |
| 待核实 | 能力未知、结论过期、版本/owner/连接变化；禁用修改直至核验完成，不把旧结论当作当前支持 |

描述结果须包含完整目标、操作标识、采样时间、能力或来源版本，以及不可用原因/下一步。它不是长期有效的执行授权。表单预检、确认前和真正执行使用同一能力判定；快捷键与直接调用不能绕过禁用状态。界面显示可修改之后若能力失效，未发送的请求应拒绝；已经发送的请求只能如实显示实际结果或待核实，不能宣称已撤回。

操作结果继续区分 `applied / rejected / uncertain`。原生能力缺失不改用星内别名、直接写历史文件、重启工具或更换 owner 来冒充成功。Provider 内部差异由适配器处理，通用界面只展示结果与可用性。

### 自动恢复与失效规则

- 能力缓存按连接上下文、星/完整 node、Provider、原生会话、端点/owner 与版本隔离，不按工具名字全局缓存。配置或 owner 变化立即使旧结论失效。
- 原生事件、重连、显式刷新和活动页面的有界只读探测可以重新核验能力。暂不可用按有上限的退避重查；已知不支持无需高频空查，但版本/适配器变化后必须重新判断。
- 服务恢复或新版本支持该能力后，经核验自动更新动作状态，无需重启 TUI；恢复可用不自动提交先前的表单或重放操作。
- 不可达/未知不代表成员不存在，不据此删册、改属性或切换目标。过期/其他代次的探测结果不能覆盖当前会话或当前连接的状态。
- 请求已经发出且结果不明时，自愈只做只读核实和状态对账，不自动重发改名、入星或删册请求。
- 页面切换、连接切换、取消和退出释放探测 timer、订阅和请求；能力恢复不能影响其他窗口、工具或星。现有权限仍由执行端判断，不通过恢复流程放宽。
- 这里的自愈是能力重新发现、状态同步与原生服务恢复后的重新接通，不能自动创造原生不存在的功能，也不自动安装/升级工具或修改用户配置。

## 非侵入式改名的可行性

下表保留实施前调查；2026-10-27 已补充实际接入与受控原生验证，当前能力以[原生改名验收](native-rename-validation-20261027.md)为准。

| 工具 | 已查实的原生入口 | 实施与验收边界 |
|---|---|---|
| Claude | 官方 SDK `renameSession(sessionId, title)` 追加持久标题记录 | 尚未证明活 owner 的登记 name、窗口和星内路由立即跟随；不能直接承诺支持实时改名，也不能向消息管道发 `/rename` 文本冒充执行 |
| Codex CLI | 官方 app-server `thread/name/set`，支持已加载线程/持久记录并产生名称变更通知 | 当前 RPC 白名单和会话接口未接入，需验证实际 owner、版本及前端同步 |
| Codex Desktop | 当前协同 IPC 没有已接入的 rename 方法 | 不把 CLI daemon 的 setter 直接套到 Desktop owner；若未核实可靠入口则禁用并说明 |
| OpenCode 2 | 原生内核 `Session.rename` 发布同一会话的 `SessionEvent.Renamed` | 尚需核实当前版本 HTTP/client 暴露与前端同步；内核方法存在不等于已有可用外部调用链 |
| DeepSeek Harness | `ctx.sessionTitle.rename(session, title)` 核对 exact live session，提交 `session/title` 并返回新快照 | 可由已有 Host bridge 接入，不更换 owner；当前 bridge 尚未提供该操作，需原生受控验收 |

## 验证要求

先用隔离事件源验证统一监督与属性规则，再逐工具做原生受控验收。最少覆盖：空白零误入册；首条输入；恢复旧 ID；A→B→A；取消选择；同目录多窗口；每星属性不同；永久成员遇 `--rm`；切换时断线/重连/迟到事件；窗口退出；node/broker 重启保留册位、当前启动器重声明、无启动器不自动归队；无法核实时不破坏其他声明。

TUI 另验证本机/远端 node 的匿名和未入星会话、完整目标锁定、重复入星不变属性、删除后即时路由失效、真实名称变更与按名寻址一致、其他 TUI 自动刷新、来源不支持改名、提交后取消/断线，以及临时会话不误删已有永久成员。使用 npm/Vitest、隔离 broker/node/原生来源及真实受控终端；按仓库要求完成检查，不以固定覆盖率代替行为验证。

统一接口还须验证未知第五工具无需改通用 TUI、同 Provider 不同端点能力不同、只禁用不支持的操作、页面与执行端一致拦截、能力暂失→恢复自动启用、版本/owner 变化使缓存失效、旧探测迟到不覆盖新状态、对结果不明的写入零自动重发，以及刷新/切页/退出后的资源释放。

普通隔离测试不能代替原生窗口事件验收。以上调查表记录实施前事实；实施阶段随后在独立 profile、临时工作目录及 loopback 模型下运行了本机已有 Claude/Codex 和真实终端，结果及限制见[本轮验证](session-selection-membership-validation-20261026.md)。没有连接生产远端或修改用户原生配置；需求交接按用户指定执行，其他工具适配仍归「多工具适配」后续计划。
