## 范围与已批准约束

- 终端自动入星跟随本窗口真正选定的完整原生会话 ID：空白先等待，直接新聊在首条用户消息后入星；选择/恢复 A 后入 A。A→B 只释放本窗口对 A 的声明再声明 B；取消选择、压缩上下文和无法核实不冒充切换或退出。
- 每星核实实际永久/临时属性。`--rm`、重连、重播及 resume 不得降级或删除已有永久成员；临时释放核对有效声明所有权，不影响其他窗口。依最终统一批准规则，所有工具取消裸原生 resume 自动归队，旧/手动永久成员同样适用；永久册位保留。node 普通断网重连重放当前内存声明，进程重启后由仍活着的 crosschat 启动器恢复当前声明；无启动器的手动成员通过 TUI/显式 adopt 恢复。
- TUI 沿用统一的“TCP 星→node→该 node 的具体会话”入口，手动加入为永久成员。桌面/Web 不要求启动器或自动读取标签页；加入 A 后 GUI 切 B 不自动让未登记 B 入星。
- 入星由目标 node 重新核实原生会话，权威星册确认后显示成功。删除只撤当前星资格且使相应成员路由立即失效，不删原生聊天、不停工具、不影响其他星。列表自动反映其他操作端变化；请求发出后丢回执显示待核实，不自动重发。
- 名称只取原生会话真实名称。改名仅经已核实的公开原生接口，并验证活前端、node 与星内寻址同步；没有可靠入口或不能核实时按实际能力禁用。不得仅写 `roster.name`、增加星内会话别名、改安装包/聊天文件/数据库或另建原生 owner。
- 本批不增加 TUI 永久/临时切换或手动临时成员功能；不加入安全 skill、敏感信息规则或项目目录权限限制。既有 C08 的技能安装任务独立保留，不扩成安全改造。
- 类型与命令以C14最终批准合同为准；[现有类型说明](../tool-types.md)保留作实现说明，不提前称为永久合同。当CLI/Desktop对应不同实际端点时，目标类型须能够区分；OpenCode共用服务仍按已批准的共享类型处理。成员身份、去重、选择事件与改名目标不能丢失类型限定，也不能因指定类型无owner而跨类型回落。
- 强制复用共享操作接口：稳定 `providerId` 注册适配器，在适配器内部核实 CLI/Desktop/Web 的实际端点、owner 和版本；通用 TUI 只消费各操作描述和结果，不增加逐工具名称分支。能力按查询、入星、删册、原生改名等分别声明，不支持改名不能连带禁用本来可用的成员操作。
- 能力统一为可执行、不支持、暂不可用、待核实；未知工具/未注册适配器/未核实能力时，相关修改默认禁用并说明。表单、快捷键、确认前和执行端使用同一核验，结果保留 `applied / rejected / uncertain`。能力恢复只重新启用动作，不自动提交旧表单或重发结果不明的写操作。

## 共用基础层依赖

以下 S01—S06 是既有共用能力的依赖标签，不是新活动任务。共享基础层已于 2026-10-27 完成[开发验收](session-selection-membership-validation-20261026.md)，后续[原生改名补验](native-rename-validation-20261027.md)记录实际工具能力边界。复用 `src/application/session-selection.ts`、`src/application/session-operations.ts` 及现有 node/broker/TUI 接缝，并与交接会话共用[批准设计](session-selection-membership-design-20261026.md)。本会话只承担 OpenCode/Harness 的事实核实、适配接线及相应验证，不能拿共享层通过代替这些工具的验收。

| 依赖 | 共用基础层出口 | 本会话消费方式 |
| --- | --- | --- |
| S01 窗口生命周期与可取消监督 | 明确窗口/前端归属和有序事件：等待、已选完整 ID、首条用户输入、确实退出、暂无法核实；监督按当前会话代次处理 attach/重连/释放，迟到回调不挂回 A 或删除 B。只读发现不产生这些写副作用。 | OpenCode CLI 及未来具备可靠终端事件的工具提供原生信号；不猜当前窗口。 |
| S02 逐星属性与声明所有权 | broker 权威返回实际永久/临时属性；node/监督按实际属性和本窗口声明释放。永久＋`--rm`、普通重连/重播不降级；一个窗口退出不清掉其他窗口声明。永久册位保留，恢复在线由当前启动器声明或 TUI/显式 adopt 驱动，裸原生 resume 不归队。 | 工具复用同一 attach/release 规则，不自行调用无条件删册代替释放。 |

| S05 TUI 动作与有界刷新 | 通用目标锁定/能力禁用/确认/待核实展示；成员和会话活动列表每 2 秒有界刷新，输入/详情/确认时挂起，返回重核并保留完整目标；其他操作端的变化可见。本人成功后立即重读。 | 接入通用动作与 watch，不为每种工具复制表单、刷新循环或成员制。 |

[接入规范](tool-integration-standard.md)已完成制定与审计；讨论前的[类型技术验证](tool-type-validation-20261028.md)证据保留。本轮C14整改和验证按已批准合同实施，逐入口原生来源能力和例外方案仍须收口，通用状态机的隔离通过不代表各原生入口全通过。发信来源自动识别、人工确认的跨会话分类复用及逐调用核验属于C14先行范围，不推迟到C15。本批增强仍需按各自范围验证，不用基础验收代替增强验收，也不反向阻塞基础阶段或重复询问用户已经批准的成员行为。

S06 的共享缓存至少按连接上下文、星、完整 node、Provider、原生会话、端点/owner 与版本隔离；配置、端点、owner、版本或适配器变化使旧结论失效。暂时失败不能固化为不支持；已知不支持不高频空查，但版本/适配器变化后重新判断。重连/事件/显式刷新及活动页面的有界只读探测可以恢复能力，无需重启 TUI；旧代次结果不得覆盖新目标。切页、切连接、取消和退出释放请求、timer、订阅。

自愈只允许只读核实、状态对账及恢复动作可用性，不自动重发入星/删册/改名、不提交旧表单、不为修复未知状态删册或改属性、不自动安装/升级工具或修改用户配置；不得通过别名、改历史/数据库、新建 owner 或重启原生工具伪造能力。现有执行端权限仍然生效。
