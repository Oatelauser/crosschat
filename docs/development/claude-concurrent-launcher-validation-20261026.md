# Claude 同目录匿名并发启动修复与验证

2026-10-26（Asia/Shanghai）。

## 用户批准与范围

用户确认同一目录、同一颗星可以同时启动两个匿名 Claude 会话，各自独立收发及退出；另要求正常启动不显示“attach 自动，异常见日志”，真正失败时显示原因与完整日志路径。用户最新要求“安全不管了，先解决其他问题吧”，因此本轮不修改 skill、安全规则或项目目录访问权限。

此前启动提示的独立修复与检查结果保留于 [启动器诊断验证](launcher-diagnostics-validation-20261023.md)。本记录补充并发会话归属与 `--rm` 回归结果，不替换历史验收事实。

## 根因与修复

- 并发问题不是目录锁。原启动器比较全局会话快照后选择最新新增项；两个启动过程重叠时可能同时认领第二个会话，导致入册与退出清理相互干扰。
- Claude 包装器现在从实际启动的原生子进程取得 PID，并只认领登记 PID 相同的会话。尚未取得 PID 或未发现匹配时继续等待，超时明确报错，不回退选择其他会话。
- 原生 `--resume`、`--continue`、`--session-id` 参数原样传递；已有会话 ID 可由本次新进程重新入星。未注入或改写原生会话 ID。
- Claude 入星不再为建立无关差分基线而等待 Codex 扫描；Codex、OpenCode 只扫描自身来源建立基线。
- `--rm` 两种参数顺序使用同一现有解析与临时成员生命周期。独立会话退出只移除自己的册位；本轮没有另改 `--rm` 解析规则。
- 正常入星预告已移除。失败显示具体原因、已知错误码、适用星名和实际日志完整路径；错误日志不可写时明确报告写入失败。成功确认与重连仍写日志。

## 验证边界与安装状态

用户未提供最初 `--rm` 报错全文，后来反馈该现场现象已消失；无法确认该历史报错的独立原因，不能将上述受控回归表述为原现场报错已重现并修复。

本轮未启动真实 Claude、发送生产消息、连接远端或修改用户配置。PID 回调另用真实 Node 子进程验证；现有原生 live 测试中的登记 PID 与子进程 PID 一致断言提供历史契约参考，不计作本轮原生并发验收。

自定义 shell 启动脚本须以 `exec` 启动原生 Claude，使原生进程保持被启动的 PID；脚本另起子进程且自身继续存活时，本轮实现会明确报无法匹配，不猜测后代进程。此限制已写入 [使用说明](../broker.md)。Linux/macOS 的真实原生并发没有在本轮复测。

仓库源码、本机构建与使用说明已更新；没有安装、发布或升级远端 Linux 上的 crosschat。远端已安装版本不会自动获得这些修复。
