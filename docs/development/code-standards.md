# 核心改造与 TUI 代码规范

2026-10-21。适用于本轮新增代码和实际修改的模块；每个实施任务同时验收代码规范与功能。

当前D01/D02已获用户功能变更授权：新远端完整只读发现、立即撤钥断连及明确撤权后暂停保障。用户明确本次直接升级，不做旧端兼容、降级或混版适配；下述保留契约以此批准范围为例外，不扩无关功能。

## 1. 修改范围与功能契约

- 保留已有 CLI 文本/JSON、退出码、默认扫描范围、补投、权限、册位、管理冷热路径和清理规则。
- 符合既有规格的问题修复与内部提取可以直接推进；涉及既有功能变更，先提供现状、拟改行为、影响和兼容方案，等用户同意。
- 已明确的 TUI 需求不重复审批；不能以“重构”或“修 bug”名义扩大原有功能。
- 随修改改善命名、类型、重复逻辑和职责；整理限于相关模块，不夹带整仓格式化或无关搬迁。
- 一个变更应有明确目的和可独立检查的行为结果；目录数量和任意行数上限不作为质量目标。

## 2. 模块依赖与接口

- CLI/TUI 是入口和展示；应用模块返回结构化结果，不依赖 CLI/TUI 或它们的输出字符串。
- 查询与修改分开。配置/选择器模块不导入 NodeClient、命令入口或 TUI。
- 通用表格和资源页不直接访问文件、启动子进程、打开 WS 或修改台账，通过应用接口调用。
- 工具原生差异留在 Provider Adapter；本机/SSH/TCP 差异留在 Context Adapter。
- 公共接口保持小且完整，隐藏超时、清理、分页等复杂度；不为每个函数制造转发层或全能管理类。
- 纯类型导入用 import type；区分运行时和类型依赖，禁止新增运行时依赖环，不用动态导入掩盖环。
- 保留现有有价值的依赖注入和共享状态 owner，不为减少文件行数拆散同一生命周期状态。

## 3. 模型与扩展

- Provider ID 可扩展，原生 ID 视作不透明字符串；通用页面不散落 Claude/Codex 分支。
- 内部会话键包含连接上下文、Provider 和原生引用；名称可空，不作唯一键。
- 完整 ID、短 ID、临时行引用明确区分，原值不因展示截断而丢失。
- 查询结果提供分页游标、完整性、采样时间和每来源错误；取消/失败/旧端上限不能当作完整。
- 状态保留原值，翻译由登记提供；未知状态和第三工具属性可展示，不降级假装 Codex。
- 支持发现、投递、启动、诊断等能力分开声明；不要求所有工具实现同样功能。
- 旧协议和存储格式的限制隔离在兼容 Adapter；修改持久键、ref、origin 或 wire 须先批准兼容方案。

## 4. 读取、边界校验与错误

- TUI 查询不得补投、备份/重建配置、生成钥匙、自动修复或启动原生会话。
- 区分未配置、空数据、不可读、损坏、不可达、部分结果与过期缓存，错误携带来源和下一步。
- 文件 JSON、SSH 输出和网络帧先按 unknown 接收，再验证所需字段；类型断言不代替运行时校验。
- 新读取器兼容旧载荷缺失字段；不能未经批准全局收紧现有 parseFrame 行为。
- 日志有界读取、处理轮转；查询复杂度和刷新频率明确，避免全量扫描和审计自刷。
- 记录足够的错误上下文，不将 key、adminKey、鉴权证明或完整秘密配置写入普通日志/详情。

## 5. 异步、取消和资源所有权

- 可取消读取接受 AbortSignal 或等效取消接口；换页/换上下文释放旧查询，迟到结果不得覆盖新页面。
- timer、listener、socket、文件句柄、子进程都有明确 owner 和清理路径；使用 finally/dispose 收口。
- 同步探测、进程扫描等不得阻塞 TUI 输入循环；改为异步或隔离执行，保留原判定语义。
- 写请求发出后取消只能停止等待，不能宣称回滚；超时显示待核实，非幂等写操作不盲目重试。
- 退出、异常、Ctrl+C 都恢复终端并释放轮询、连接和输入监听。

## 6. 管理、权限与确认

- broker 在跑时通过现有管理插座写；无回执失败不能冷回退直接写文件。
- 冷路径复用原子写和局部 mutation，禁止旧内存快照整文件覆盖；静态台账不保存运行时 online。
- UI 按能力置灰，后端继续权威鉴权；保持三层管理权限和挑战应答，不新增裸钥降级。
- 写动作归对应资源列表，详情只读；弹层固定上下文、稳定目标 ID、影响与返回规则。
- 确认前重新核对权限和目标；失败保留输入，成功回原列表并保留选择/筛选/滚动位置。
- D02按获批规格实现立即撤权，只有实际失效后才显示完成；明确撤权暂停该星保障链，普通网络失败不误判撤权。

## 7. 显示与交互一致性

- 资源、别名、列、动作、按键、能力说明从统一登记生成，底部提示和 ? 帮助使用同一事实源。
- 输入栏同时补全命令和筛选资源；明确 Enter 行为，输入/表单模式屏蔽底层列表快捷键。
- 每列限制终端显示宽度，按字素和显示格截断，不拆组合字符；详情与复制保留完整原值。
- 中文状态加原值，原生忙闲、星籍和机器连接分别展示，不互相推断。
- 所有资源按任务简化：自动带入已知目标、说明结果和下一步；只读资源保持只读。

## 8. 工具规则渐进落地

- 保留 TypeScript strict 和现有 ESLint recommended 基线。
- 在新增/重构模块验证并逐步启用类型导入、未处理 Promise、错误 Promise 回调等规则；先确认 ESLint 的 TS project 覆盖正确。
- 用实际 import/export 图检查模块方向和循环，包含运行时 re-export 和可解析动态导入，排除纯类型边。
- 工具规则上线前用违规与合法 fixture 验证能拦截正确问题；过渡豁免有明确位置、原因和移除任务。
- 不通过整文件 eslint-disable 掩盖问题，不为引入规则批量改动无关旧代码。

## 9. 测试与任务完成

- 测试验证接口行为和失效路径，不镜像实现，不用固定覆盖率或新增用例数量替代判断。
- 有意义场景包括：只读无副作用、匿名跨页、第三测试 Provider、同 ID 不同工具、旧端部分结果、取消清理、权限拒绝、热写超时不回退、清理预览不删除、选择稳定。
- 普通测试使用临时目录、注入依赖、受控连接，不依赖真实用户会话或生产钥匙；live 验收独立说明环境和结果。
- 先完成变更对应检查，再跑 npm run check；通过后仅在新变更/失败/未决风险出现时扩展或重复检查。
- TUI 另做真实终端键盘、resize、异常退出和恢复验收；静态图和 renderer 测试不能代替终端验收。
- 每个任务完成须同时满足行为、规范、测试、相关文档和审批边界；有必需待确认/未验收内容不能宣称完成。
- 按用户要求，验收后删除活动任务条目与对应临时任务说明，并更新剩余依赖和排期；证据保留在提交/PR、批准记录或独立验收记录。
