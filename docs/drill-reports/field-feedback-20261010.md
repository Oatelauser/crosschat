## 二、四点核查（对代码实证，2026-10-10）

1. **"ref 漂移陷阱"实为安全**：ref 路由键 = 端点 + nonce（跨轮稳定，`src/ref.ts`），每轮漂移的只是轮号 c；`continueFromRef`（`src/conversations.ts:191`）命中同 nonce 的本地 shard 时轮号自愈到最新。误抄旧 ref 照常精确路由、不丢件、不串线。
2. **反向发现：--to 才有真实风险面**：`--to` 接续"该端对最近对话"（skill 本就教"一次消息一个主题"），多话题并行时可能接到另一个话题——原 skill 把精确工具（`--conversation`）表述为"拿不准才用"、把 `--to` 表述为兜底，安全方向说反了。
3. **queued 无回执 = 设计内语义**：消费确认免费搭载在业务流量上（对端下一条来信的 turn 号），这是唯一跨联邦、免轮询、免新基建的回执形态；显式回执协议 = 新状态 + 联邦侧不可达，违背低入侵约束。
4. **N/M 预算属任务层，stdin 免引号形式已存在未教**：worker 轮次预算的正确位置是派单词面（本报告自己引述"三次派单 SHA、预算、路径、停止条件齐全"——预算一直在 body 里），信封 `turn="N/M"`（`--max-turn`）只是传输层软提醒；另 `--body` 省略时读 stdin（`src/cli.ts:284`）已支持，但 skill 未把管道形式教到 shell 敏感字符场景。

## 三、工程响应（本批落地项）

- SKILL.md 三处教学修正：① 旧 ref 安全性声明 + `--to` 风险面反转（精确回复永远 `--conversation`）；② queued 消费确认语义一句；③ 管道形式扩教 shell 敏感字符场景
- 编排侧纪律（memory，不入仓）：派单词必含轮次预算与停止条件；高赌注交接靠幂等（票面可重 derive + 验收拉式），不靠投递回执
- 信封教学行保持冻结（字节零回归锚点），其"新话题或对话已推进时 --to"表述与新教学不冲突
- **明确不做**（俯瞰否决留档）：已读回执协议（新状态+联邦不可达+违低入侵）；mc3 稳定 ref（mc2 布局 v1.4.0 后冻结，且旧 ref 本就安全，收益趋零）；launcher 默认注入轮次预算（改变存量用户信封字节，软旋钮保持 opt-in）；doctor 类"检查 ref 新旧"子命令（新命令，且答案恒为"反正安全"）
