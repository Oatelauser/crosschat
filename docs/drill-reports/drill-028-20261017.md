## 八项验收

**1. 永久册 resume 即复活 ✅**
d28a（WSL，id a92da8a0-…）退出 → `下线: ⚪wsl:claude/d28a（等 resume 复活；接任 --extend-session；删 --member-remove）`；之后 tmux 内 `crosschat claude --resume <全号>` **裸起零声明** → 聚合器对账循环自动归队（node log `member-revived`），册位原样复活 → 真发 `delivered …(turn 3)`。中途另证：册在 broker 重启后仍不丢（roster 落盘），新 broker 认领旧册后扫描再次复活 d28dual。

**2. --rm 退出零痕迹 ✅（主路径）＋发现 F1（异常死亡缺口）**
d28rm2 交互启动器 `--connect drill028 --rm` 入册（`会话: wsl:claude/d28rm` 同款）；`/exit` 体面退出（包装器 detach·erase 路）→ 册内**无痕**（无下线行）→ 按名投递 `SESSION_NOT_MEMBER`（与从未入册同码）。
⚠️ 反例：d28rm 被 kill（异常死亡）→ 册位**滞留下线态不删**（多轮对账不清），投递报 SESSION_OFFLINE——见 F1。

**3. extends 胜复活 ✅**
d28old 下线后 `--adopt d28new --extend-session d28old`：成员行显示血统 `会话: wsl:claude/d28new (extends←d28old)`；投旧名 → `SESSION_SUPERSEDED: …已由 wsl:claude/d28new 接续——改投接任者 tcp:drill028:wsl:claude/d28new`；投新名 delivered。原会话同 id 回归（tmux resume）→ 上位为 `会话: wsl:claude/14efb539`（id8 形态、无名），聚合器日志每轮教学 `EXTENDS_CONFLICT: …回归不夺回——本会话按 id 寻址 tcp:drill028:wsl:14efb539，或换名重启`；id8 直达 delivered；旧名仍指接任者。**名字唯一转移口语义全链闭合**。

**4. member-remove 幂等 ✅（且异机可执）**
d28a 下线态，从 **win**（成员宿主是 WSL）执行：第一次 `已从星 drill028 册内移除：d28a`；第二次 `成员 d28a 本不在册（幂等成功，零改动）`；再投 → `SESSION_NOT_MEMBER` + 启动器入星教学。

**5. 下线报错教学 ✅**
投下线成员：`SESSION_OFFLINE: [via tcp:wsl:d28a] 成员 d28a 已下线（册位保留）——等其 resume 上线（同 id 自动复活）或 --extend-session 接任；点对点直达其特定会话可用 id8 寻址（现也下线，上线即达）`——三逃生口全文、绝不静默改投、错误回显带星段（027-F 语义顺带可见）。

**6. 跨机 resume 拒绝 ✅**
册绑 win 的 id（d28mb2）在 WSL 同 id 声明入星：broker log `machine-bound 拒绝：b9f3e13a 册在 yang，wsl 声明`；聚合器日志 `MACHINE_BOUND: …册位绑在 yang（同 id 异机不复活）——迁移走显式操作：先在 yang 执行 crosschat serve --connect <星> --member-remove b9f3e13a，再在本机重新入星`——**可照抄迁移配方**，册位未被改绑。（构造途中实证 claude 原生挡同号双活：`Session ID … is already in use`——跨机抢号在 claude 侧先被拦一层。）

**7. 多星各自复活 ✅（B 腿投递受自伤拓扑所阻，见 F4）**
d28dual `--connect drill028 --connect drill028b` 双横幅、双 launcher 落账、双 member-up；kill → **两星册各自独立翻 ⚪**；同 id resume → **两星各自复活**（两行 `会话: wsl:claude/d28dual`）；A 腿真发 delivered 且 okA 回信经星腿信封穿回。B 腿（drill028b，星心在 WSL）投递撞 `MACHINE_NAME_COLLISION`（同名同 mid 双连接）——自伤拓扑（星心机又手挂本星聚合器，同 F4），非成员制缺陷。

**8. skill 分层零跳转 ✅**
装好的 SKILL.md 87 行自足（信封解剖+照抄纪律+短柄/防伪造/轮次预算+管道两式范例+三形态各一条）；`references/`（errors/stars/advanced）三件随 install-skills 递归铺齐；doctor 递归整树比对 `✅ claude 侧 skill 与安装源一致` / `✅ codex 侧 …一致`。

## 现场发现（全部非阻塞，未修）

- **F1｜--rm 异常死亡不删册**：零痕迹只走包装器 detach·erase+墓碑路；进程被 kill 后无人上报 erase，broker 又不知谁是临时成员（temp 标记未随册落盘）→ ⚪ 滞留、投递报 SESSION_OFFLINE。与 docker --rm 语义（任何退出都清）相悖。候选小票：册条目落盘带 temp 位，或对账循环对"册内下线且本机无进程"的 temp 成员执行删。
- **F2｜`--bg` 启动跳过星 attach**：bg 形态横幅照打（"会话地址 tcp:… 直达"）但 attach 全程未发生（launcher.log 零记录、册内无此人）；正解是 `serve --connect <星> --adopt <名>` 收编（本 drill 的标准补救，幂等可反复）。建议：bg+--connect 时横幅改为提示走 adopt，防"横幅许愿、册内查无此人"。
- **F3｜adopt 硬依赖 codex daemon**：claude 会话的 adopt 在 codex app-server daemon 未跑时直接 `CODEX_PROXY_SPAWN_FAILED` 全败（非优雅降级）；`codex app-server daemon start` 后同命令即成。建议 adopt 的 codex 探测失败时降级为"仅扫 claude 会话"。
- **F4｜星心机自挂聚合器 = 同名同 mid 双连接**：broker 自挂 + 显式 `--connect <本星>` 并存时机器表出现两条同名同 mid 记录，**名字与 mid 前缀寻址全部撞死**（"加长前缀"逃生口对同 mid 双条无效）。docs 已明令星心机勿手动挂聚合器，但报错形态可再教学化（提示停显式守护）。
- **F5｜单机双 broker 不支持**：两 broker 共享一份 broker.json（身份/钥匙注册表互覆）——删文件重来会令旧 broker 钥匙全废（BAD_AUTH 风暴）；gen-key 只登记进"当前 broker.json 持有者"。多星正确形态=每机至多一 broker（本 drill 后半即改 WSL 承担第二星心）。
- **F6｜claude bg-resume 换号**：`--bg` 形态 resume 已停会话会 fork 新号（claude 自身行为，控制台明示）；同 id 复活须交互式 resume（本 drill 用 tmux pty 全程实证）或 `--session-id` 钉号交互起。028 的"同 id resume 复活"不受影响（跟的是 id 不是形态），但教学文案宜点名 bg 例外。
- **F7｜交互会话首个用户轮之前不可见**：交互会话要等首轮落盘才有会话文件，聚合器扫描在此之前看不见它（横幅地址暂不可投）。无首轮的窗口会话永远不上册。建议 stars 诊断行或横幅补一句"首轮后生效"。
- **F8｜WSL `serve --stop` 假报成功**：stop 打印"pid N 已终止"但进程仍在（后续双开防护又见同 pid）；kill -9 才真死。残留守护带旧配置再连会报 STAR_ID_MISMATCH 且反复重试，排障成本高。候选小票（linux 侧 stop 路径）。
