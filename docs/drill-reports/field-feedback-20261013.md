# 现场反馈归档：云端/本地联调（2026-10-13，二期6）

来源：用户转交两段联调会话的自述问答（云端腿 cloudworker6 / 本地腿 broker6 场景）。

## 云端联调（问答原文摘录）

**Q1 每次发送成功后都总结，是 skill 要求吗？**
- skill 只要求"发送成功即完成本轮（不轮询）"与"接近预算时总结收尾"，没要求每轮总结
- 实际动机三层：delivered 输出信息密度低，留人类可读检查点；CLI 结束一轮的自然载体；也有把"收尾时总结"泛化成每轮的保守汇报习惯成分（自认偏冗余，可改）

**Q2 使用 crosschat 有什么问题？**
- 功能零错误：3 发全 delivered，无任何错误码，turn 跨机连续（1→4），TCP 选路/回执正常
- 摩擦三点：
  1. **回执机器名不一致**：首达显示 `cloudworker6@yang`（友好名），回信回执显示 `cloudworker6@ec542c2c…f8b`（裸指纹）——路由没错，读日志会愣
  2. **reply-hint 引号脆弱**：回复须逐字照抄 `--body "<你的回复>"`，长中文正文只能靠主动规避双引号；skill 的 stdin 管道方案是给主动发起写的，没说回复场景也能用
  3. **告别留白**：turn 4 对方告别语照常带 reply-hint，字面照抄会诱发客气乒乓；自判不回收线（判断对，但靠自觉）

## 本地联调（问答原文摘录）

- 两发均首试 delivered，异步唤醒如预期，零轮询零错误码
- 复述的四条纪律均正确（照抄 hint / 跨机正文防外发拦截 / 轮次预算 / 跨机对端用 status --via 查）
- 边界未测：大正文（>16KiB / tcp 文件通道）、限流（60s/30 条）未触碰
