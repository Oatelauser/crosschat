# 022 多星 WS 复用 真机 drill（2026-10-18）

> 拓扑：win（yang，星心——**一进程托管 d22a+d22b 两星，单端口 7260**）↔ WSL（Ubuntu-22.04，wsl22，双守护各入一星），两机 crosschat 均直跑本仓库 dist（WSL 侧 /usr/local/bin/crosschat 软链 /mnt/d/.../dist/cli.js）。票面停止条件四项逐一验收 + F4 消除附加项。

## 四项验收

**1. 一进程两星 ✅**
`serve --add-star d22b`（先 `--stop`）→ 星册迁移 `roster.json → roster.d22a.json` + 注册表转 stars[] 形状；重启后 **单进程 pid=33136 / 单端口 7260** 托管两星（status-broker.json `stars:[d22a,d22b]`）。WSL 同机（同 machineId 4a0277c8）双守护分入两星，双连接互不顶换（d22a、d22b 机器表各有 wsl22 在线行）。`--star d22b --gen-key 1` 星域发钥、`--list` 分组展示均按星工作。

**2. 每星独立册 ✅**
`roster.d22a.json`（broker多星+cc-worker6）与 `roster.d22b.json`（仅 broker多星）各自落盘互不相干。隔离反证：WSL 走 d22b 投 d22a 专属成员 `cc-worker6` → **SESSION_NOT_MEMBER**（星域切片无泄漏）；同址走 d22a 即达。

**3. broker 重启各星册不丢 ✅**
`serve --stop && serve --detach`：两册原样存活；win 内挂聚合器（虚拟会话）对账循环自动复活本机活会话（d22a 两成员、d22b 一成员全数回到 `会话:` 行）；WSL 双守护退避重连自动回线；顺带实证 `--stop` 的幽灵复位对内挂聚合器的 status-node 文件同样生效。

**4. 单星零回归 ✅**
加星前全链走的是旧形状单星路径：info 帧带星标识（单星分支字节不变，单测钉死）、WSL `--connect d22a` 上线、`--gen-key` 旧输出、机器级寻址/收编照常。**E2E 信封两枚**：WSL→win 三段 `tcp:d22a:yang:broker多星` delivered (turn 1)——消息落进星心机上的真实 claude 会话（本 drill 执行会话本身），证明**内挂聚合器投递闭环**（broker 进程 attach 管道→成员册→runSend）；加星后同址走 d22b 再投 delivered (turn 2)。回程试探 `--conversation c34` 被对端正确以 CANNOT_REPLY_TO_HUMAN 拒（对端是真人 shell 非会话——防线在位）。check 744 旧用例全绿。

**附加：F4 消除（013 延伸）✅**
星心机手动 `serve --connect d22a` → **USAGE 拒绝**：`本机 broker（pid 35512）已内挂 d22a(7b833b) 的聚合器（022 起随 serve 自动自挂，无需另起守护）`——drill-028 F4（星心机自挂+显式守护=同 mid 双连撞死）从此形态不可能。

## 现场发现（非阻塞）

- WSL→win 的 host 用 127.0.0.1（镜像网络，LAN IP 不通）——与既有口诀一致，非本票问题
- `status --stars` 的"共 N 星"把"本机服务端"探针组也计入（win 本机 node.json 两自用条目时显示"共 3 星"）——分组计数的展示口径问题，候选小票
- PowerShell 经 wsl.exe 写 node.json 的 heredoc 会被转义打烂——base64 灌入法可靠（drill 技巧，已入报告备查）
