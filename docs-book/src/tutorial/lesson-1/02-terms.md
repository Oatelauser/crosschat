# 1.2 术语

## 术语表

| 词 | 一句话 | 出现的地方 |
|---|---|---|
| 会话（session） | 一个运行中的 claude 实例，登记在本机会话注册表里 | 名单、信封署名 |
| 线程（thread） | codex 侧的对话单位，住在 codex 自己的名册里 | 名单、投递目标 |
| 名字 | 会话/线程的人读地址，`--to` 按它找人（全名精确，或唯一前缀） | `send --to`、名单 |
| 短柄 cN | 本机会话引用的两字符缩写（c21 这样），照抄即路由 | 信封回信命令、回执行尾 |
| 信封 | 消息的包装：署名、轮次、回信命令、正文，收方看到的就是它 | 每条到达的消息 |
| 轮次（turn） | 对话的第几来一回，信封里形如 `turn="2"`，带预算时 `turn="13/40"` | 信封、回执 |
| 投递三态 | delivered（送达）/ queued（对方忙已入队）/ parked（已暂存自动重投） | 每条 send 的输出 |
| 发件箱 | parked 消息在本机的暂存队列，看门狗自动重投，满 200 条诚实拒绝 | parked 回执、排查 |

## 会话与线程

两个词说的是同一层东西的两家方言：claude 那边叫**会话**，codex 那边叫**线程**。crosschat 不另造统一身份——投递时各用各的原生 id（claude 会话 id、codex 线程 id），名单也只是把两家的登记册拼在一起给你看。所以"会话"与"线程"在本书里可以当同义词读，真到投递那一刻，走的是两条不同的腿（[1.4 通信机制](04-mechanism.md)）。

## 名字与短柄

**名字**是给人看、给 `--to` 用的：claude 会话在启动时用 `-n` 命名，codex 线程用 `/rename` 随时命名。名字可以带空格（命令里加引号），可以只写前缀——只要前缀在名单里唯一命中一个人。没起名的会话也有办法够到（codex 未命名线程用 id8 寻址，[1.3](03-first-chat.md)会亲眼看到）。

**短柄**是给 AI 照抄用的：`c` 加一个数字，就两个字符。每对会话的每段对话在本机有一个柄，信封里的回信命令用的就是它——回信方逐字照抄，不手打、不截断。为什么需要它：完整的对话引用有八十多个字符，让 AI 手抄一遍是最脆弱的环节；两个字符的柄把这件事变成不可能抄错。柄背后的机制（本机分片、同对话跨轮不变、旧柄照发也准）在 [1.4 回信怎么认路](04-mechanism.md#回信怎么认路)。

## 信封与轮次

**信封**是每条消息到达时的样子：一行署名（谁发的）、一行回信命令（怎么回）、正文、一个闭标签。它不只是格式——回信需要的全部路条就坐在里面，收到信封的会话照抄其中一条命令就能原路回信，不需要知道对面住在哪、叫什么。📨 这个符号在全书里就指它：agent 收到的外来消息信封。

**轮次**是这段对话的第几来一回。第一封信 `turn="1"`，回信就是 2，再回是 3——两边都不用记，引用里自带计数器，每封信自动 +1。它是对话的里程表：turn 越大，说明这段对话已经往返越多轮。带上预算时形如 `turn="13/40"`，超过预算不硬拦，但提醒你该总结收尾了——轮次是协议给上下文压力的唯一答案，这一点 [1.4](04-mechanism.md#上限与限流)要专门讲清。
