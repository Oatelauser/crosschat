# 投递与结果

## 模式语义

`queue` 等目标当前轮完成后处理；目标空闲时直接唤醒。

`steer` 忙时追加到当前任务，空闲时启动新一轮。它不会撤销已经执行的操作。选择规则以主文件为准；接收端不支持时报告能力问题，不悄悄删除参数改成排队。

## 按实际结果继续

| 结果 | 含义与下一步 |
|---|---|
| `delivered` | 接收通道已受理；不等于对方已执行 |
| `queued` | 已交对方队列，等待消费；无需重发 |
| `parked` | 已在本机暂存并安排补投；无需重发 |
| `confirmed` | Codex 目标历史中已观察到本条正文；不代表任务完成 |
| `unconfirmed` | 尚未在历史中观察到；不能据此重发 |

请求的模式、接收状态和回执是不同证据，不能互相替代。超时或报写入不明时，先按 [errors.md](errors.md) 核实，避免重复投递。

## 发送后

发送成功即结束这次发送动作，继续自己的任务或结束本轮。回复会异步进入当前会话，**不轮询 `status` 等回复**。纯确认或告别无需继续互相回执。
